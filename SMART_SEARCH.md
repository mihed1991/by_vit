# Умный поиск BYVIT — первая версия

Лупа в шапке и каталог используют один модуль `js/search-utils.js` без ИИ, внешних API и новых зависимостей. Существующие цели и `productIds` определяют состав подборок; карточки, фильтры, корзина и маршруты сохранены.

## Админка → Цели

В каждой цели откройте «Умный поиск: фразы и пояснения». Введите фразы покупателей по одной на строку. Название цели участвует автоматически. Для старых шести целей при первом открытии доступна 51 стартовая фраза, исходные товары не изменяются.

Для выбранных товаров можно указать приоритет 0–100 и проверенное пояснение (до 400 символов). Без пояснения сайт сообщает только о включении товара в подборку, не придумывая его свойства. Новые цели, скрытие целей, удаление товаров и изменение остатков учитываются по текущему каталогу.

«Проверить умный поиск» использует текущие, ещё не сохранённые поля редактора. После проверки нажмите «Сохранить цели», чтобы обновить витрину. API сохраняет фразы и правила вместе с настройками сайта; они также попадают в обычный резервный архив данных.

## Правила

- Точное название или бренд имеют приоритет над распознаванием цели.
- Запрос с типом товара и целью пересекает соответствующую категорию и товары подборки.
- Несколько распознанных целей требуют выбора, который сохраняется в параметре `searchGoal` рядом с `q`. Изменение запроса сбрасывает этот выбор. Ссылки, фильтры и возврат браузера сохраняют состояние.
- Нормализация учитывает регистр, «ё», знаки и пробелы. Ограниченный поиск по похожему написанию включается как запасной вариант; пользователю сообщается о близких совпадениях.
- Значимые неизвестные слова не отбрасываются. Запросы с отрицаниями, «без…», похудением или медицинской задачей не получают автоматическую товарную рекомендацию: пока нет проверенных структурированных правил для таких ограничений.
- Ранжирование: совпадение → редакционный приоритет → наличие → исходный порядок. Недоступные точные совпадения не скрываются.
- Поиск выполняется в браузере. Запросы не записываются в новую аналитику и не передаются сторонним сервисам.

## Проверки

`node scripts/check-search.js` — правила и защитные случаи.

`node scripts/check-search.js --browser` — интерфейс, мобильная версия, фильтры и сохранение настроек на изолированной тестовой базе. `BYVIT_E2E_SCREENSHOTS` позволяет сохранить скриншоты.

Статический экспорт включает модуль и стартовый словарь. Как и другие настройки статической витрины, редактирование на GitHub Pages не является серверной публикацией: для рабочего магазина нужен API или обновлённый статический экспорт. Текущая рабочая база данных не изменена автоматически.
