# Блог BYVIT

## Управление

Запустите Node 24 (`npm start`) и откройте `/admin.html`, раздел **Блог**.
Здесь создаются статьи, рубрики, обложки, авторы, SEO-поля, текстовые блоки
и подборки до четырёх существующих товаров. Адрес статьи закрепляется после
первого сохранения. Черновик и архив не выдаются публичным API, не попадают в
карту сайта и не открываются по публичной ссылке. Архив можно вернуть через редактор.

Для публикации требуются заголовок, уникальный адрес, дата, краткое описание и текст.
Предпросмотр несохранённых материалов находится внутри админки, в изолированном iframe
без исполнения скриптов. Из текста не исполняется HTML. Загрузка: JPG, PNG, WebP до 10 МБ.

Обложка: **1200 × 600 px (2:1)** для главной, списка и статьи на всех устройствах.
Главный объект ближе к центру; заголовок размещается в интерфейсе под обложкой.
Встроенные изображения статьи: до 1600px по длинной стороне, с описанием и подписью.

На главной показываются три последние опубликованные статьи; отмеченные «На главную»
имеют приоритет. Включение блока отдельно регулируется для компьютера и телефона.
Без публикаций блок скрывается. На странице списка — 9 статей и счётчик результатов.
На телефоне рубрика выбирается из компактного списка с количеством статей;
на компьютере до шести рубрик показываются кнопками, дальше — тем же списком.
Переключение рубрики возвращает к первой странице. Пагинация не разрастается:
показываются первая, текущая и последняя страницы и стрелки назад/вперёд.

## Публикация

- На Node-сервере: сохранение статуса «Опубликовано» делает статью доступной посетителям.
  При обновлении исходников нужно перезапустить Node, чтобы загрузились новые серверные модули.
- На GitHub Pages: админки и базы данных нет; публикуется результат статической сборки.
  Кнопка «Экспорт для GitHub Pages» скачивает `byvit-blog-published.json`, только с
  опубликованными статьями. Загруженные через сервер изображения включаются в JSON.
  Сохраните экспорт в непубличную локальную папку и выполните:

```sh
BYVIT_STATIC_BLOG_FILE=/absolute/path/byvit-blog-published.json npm run build:static
```

Для автоматической сборки GitHub Actions можно сохранить этот **публичный экспорт**
как `content/blog.json` в репозитории: сборщик подхватит его без переменных окружения.
Туда нельзя помещать полный бэкап админки; используйте именно кнопку экспорта блога.

Публикуйте **dist/**. Сборка создаёт `/blog/<адрес>.html`,
включает текст статьи в HTML, SEO-метаданные, BlogPosting и ссылки в sitemap.xml.
Изображения из экспорта превращаются в отдельные файлы с хешированными URL.
Без переменной сборщик использует `content/blog.json`, если файл существует;
иначе — стартовое содержимое `js/data.js`. Экспорт относится
только к блогу; товары для связей должны уже присутствовать в публикуемом каталоге.
Не добавляйте резервные копии админки с заказами и секретами в публичный артефакт.

## Проверки

`npm run check:blog` — изолированный сервер и база в системной временной папке;
проверяет публикацию, закрытость черновиков, редактор, предпросмотр, ссылки на товары,
корзину, рубрики, пагинацию, пустые состояния и ширины 320–1440px.
`npm run check:static` — статические страницы, вложенные URL, хеши ресурсов и отсутствие
обращений к API. Для снимков задайте `BYVIT_E2E_SCREENSHOTS=/absolute/path`.

Три стартовых материала написаны для этого проекта, не скопированы с референса.
Новые материалы о здоровье публикуйте с проверяемыми источниками и реальным авторством.
Комментарии, рассылка и ИИ-кнопки не реализованы.
